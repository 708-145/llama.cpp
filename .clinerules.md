## Tools: what works, what doesn't

| tool | status | why |
|---|---|---|
| `read_files` | works | single-file reads; use `start_line`/`end_line` on files > 2000 lines |
| `editor` | works | small, precise edits; max ~6000 chars per call |
| `run_commands` | **30 s timeout, kills shell** | any command > ~30 s is killed mid-run (builds included). Always check `/tmp/dna_build.log` after starting a build |
| `search_codebase` | **brittle on this tree** | forks/ contains exllamav3, transformers, vllm, mergekit, etc. — over 1800 files, broad queries time out after 30 s. Prefer `grep -rn` via `run_commands` scoped to subdirs: `llama.cpp/src/`, `llama.cpp/common/`, `llama.cpp/tools/server/` |

**If a search / grep hangs or times out:** narrow to `llama.cpp/src/` or a
specific file with `grep -n`. Reserve `search_codebase` for `llama.cpp/`-only,
or avoid it entirely.

**Do not run long commands without backgrounding them** (see Build below).
Plain `cmake --build` will be killed at 30 s, unlinking the binary mid-link
(`gmake[3]: *** Deleting file 'bin/llama-cli'`).

## Build (the working recipe)

Your compile instructions live in `llama.cpp/DNA.md:234` — keep them verbatim:

```bash
cd /mnt/c/Users/tobia/Desktop/tobifun/sandbox/forks/llama.cpp
cmake -B build -DBUILD_SHARED_LIBS=OFF -DLLAMA_CURL=OFF
# incremental (REQUIRED, backgrounded — see below)
setsid bash -c 'nohup cmake --build build --config Release -j1 --target llama-cli \
  > /tmp/dna_build.log 2>&1; echo DONE:$? >> /tmp/dna_build.log' \
  < /dev/null > /dev/null 2>&1 &
```

Then poll:

```bash
sleep 28; tail -n 15 /tmp/dna_build.log
ls -lh build/bin/llama-cli
```

- Use `-j1` (not `-j4`): `-j4` with several heavy TUs gets killed with
  `*** Deleting file 'bin/llama-cli'` on timeout. `-j1` survives the 30 s tool
  limit because the process is detached with `setsid` + `nohup`.
- First full build takes ~10–15 min. Incremental rebuilds touch unity files and
  the tools layer (`tools/server`, `tools/cli`) — expect ~5–10 min.
- Config: `BUILD_SHARED_LIBS=OFF`, `DLLAMA_CURL=OFF`, per `DNA.md`.

## Running DNA (verified commands)

The CLI wraps a server; `--dna` is a general flag (`common/arg.cpp`, env
`LLAMA_ARG_DNA`) and forces `load_mode=mmap` + `--no-repack` — no `--fit off`
needed. Per-turn DNA stats print server-side at `LLAMA_LOG_ERROR` (always visible):

```bash
./build/bin/llama-cli --dna -m ../../smollm-f32.gguf -p "hello" -n 5 -lv 3
LLAMA_DNA_CALIB=32 ./build/bin/llama-cli -m ../../smollm-f32.gguf -p "hello" --dna
```

- `-lv 3` = INFO: needed for DNA startup and the per-turn line
- `LLAMA_DNA_VERBOSE=1` only controls the destruction-time dump (destructor)
- Error cases to re-verify after any rebuild:
  ```bash
  ./build/bin/llama-cli --dna -m ../../smollm-f32.gguf -p "hello" --load-mode none
  # must throw: "error: DNA requires memory-mapped weights, but --load-mode was set to "none""
  ```

## Git

- `git` inside WSL on a Windows-mounted tree is slow (status/diff can exceed 30 s → times out).
  Use `timeout 15 git --no-pager …` and narrow paths: `git diff HEAD --stat -- DNA.md`
- **Never `git checkout -- <file>` or `git stash` DNA.md** without backing up first —
  your uncommitted edits there are the only copy. Back up with `cp DNA.md DNA.md.bak`
  before any restore. (`DNA.md` was already clobbered once this way.)

## Caveats / hazards

1. `tools/server/CMakeLists.txt` adds `target_include_directories(${PROJECT_SOURCE_DIR})`.
   A bare `#include "llama-dna.h"` fails from server code — use
   `#include "../../src/llama-dna.h"` in `tools/server/server-context.cpp`. Also,
   `src/llama-cparams.h` (internal) is distinct from `include/llama.h`
   `llama_context_params` (API) — `cparams.dna` reads collide; check both.
2. Platform demotion of `load_mode=mmap` in `src/llama-model.cpp:1700` is now a
   hard error (`std::runtime_error`). If a device reports `mmap_support=false`,
   DNA will throw at load rather than warn.
3. `common_fit_log_scope` in `common/fit.cpp` (`llama_log_set` lambda that drops lines
   containing `"DNA"`) — also drops user-visible DNA lines during the fit probe.
   Intended, but confusing if you wonder where `DNA enabled` went during fit.
4. Windows GUI vs WSL: this box is a **Windows-native GUI** with dev inside WSL.
   Paths in `file_content` errors strip the `/mnt/c/Users/...` prefix — don't
   trust `content` file paths in user messages.
